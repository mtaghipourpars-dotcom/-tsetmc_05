# معماری سامانه و موتورهای تصمیم

## Engine A — Asset Rotation
مقایسه و چرخش بین دارایی‌های منتخب (در این مرحله هشت صندوق تاریخی):
موج، شتاب، اهرم کاریزما، توان، عیار، کهربا، آلتون و اعتماد پارسیان.

ورودی‌ها: OHLC/حجم روزانه، ویژگی‌های محاسبه‌شده، هزینه معاملات و مفروضات لغزش.
خروجی: دارایی منتخب، زمان تغییر، اندازه موقعیت، ریسک ورود، منحنی سرمایه و دفتر معاملات.

وضعیت: بازپخش روزانه و نسخه Risk-Limited در محیط تحلیل اجرا شده؛ اجرای واقعی صف تأیید نشده است.

## Engine B — Short-Term Stock Scanner
هدف: رتبه‌بندی سهام برای افق ۱ تا 10  جلسه معاملاتی.

لایه‌های لازم:
1. Market Regime: شاخص کل، هم‌وزن، breadth و روند.
2. Universe: حذف نمادهای فاقد نقدشوندگی/داده کافی.
3. Liquidity & Exitability: ارزش معاملات، گردش سهام شناور، عمق مظنه، ظرفیت خروج و روزهای قفل.
4. Flow: خرید/فروش حقیقی، جریان حقوقی، ارزش و پایداری صف؛ با برچسب کیفیت داده.
5. Momentum/Relative Strength: بازده نسبی و شتاب، بدون استفاده از آینده.
6. Event Risk: افشاهای کدال، توقف، بازگشایی، افزایش سرمایه و رویدادهای مقرراتی.
7. Ranking: امتیاز احتمال رشد در کنار هزینه و ریسک خروج.
8. Trade Plan: ورود، حد ابطال، هدف، حد زمانی، trailing و اندازه موقعیت.

وضعیت: مشخصات طراحی موجود است؛ بک‌تست جامع سهام هنوز انجام نشده است.

## Engine C — Portfolio Allocator
ترکیب خروجی A و B با سقف ریسک کل، سقف صنعت، هم‌بستگی، وجه نقد، محدودیت تمرکز و سناریوی بحران.

## Data Layer
هر رکورد باید حداقل شامل این مشخصات باشد:
- instrument_id و symbol؛
- timestamp و timezone؛
- source؛
- data_class: LIVE / HISTORICAL / SIMULATED / DEMO / ASSUMPTION؛
- adjustment_method؛
- completeness / quality flags؛
- ingestion_time و source_hash.

## Execution Layer
سفارش‌ها باید با وضعیت‌های NEW / PARTIAL / FILLED / CANCELLED / REJECTED / QUEUED ثبت شوند. داده روزانه OHLC به‌تنهایی امکان بازسازی ترتیب صف، لغو سفارش، اجرای جزئی یا ظرفیت واقعی خروج را نمی‌دهد.
