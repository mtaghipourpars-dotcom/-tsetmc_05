# وب‌اپ دیدبان: پایگاه داده بازار سرمایه

دیدبان یک برنامه قابل اجرای محلی با پنل فارسی، FastAPI و PostgreSQL است. هدف آن دریافت، نگهداری و بررسی اطلاعات بازار است؛ برنامه سفارش خرید/فروش ارسال نمی‌کند.

## شروع در ویندوز

۱. کل مخزن را دریافت کنید تا پوشه Data کنار market_data_service باشد.
۲. Docker Desktop و Python 3.12 نصب باشند. Docker Desktop را روشن کنید.
۳. داخل market_data_service فایل start.bat را اجرا کنید.
۴. پس از راه‌اندازی، http://localhost:8000 را باز کنید.

start.bat با setup_env.py تنظیمات اولیه را می‌سازد و کلید مدیریت تصادفی ایجاد می‌کند؛ کلیدهای سرویس موجود را تغییر نمی‌دهد. مقدار ADMIN_TOKEN در فایل محلی .env کلید مدیریت پنل است. BRS_API_KEY کلید ارائه‌دهنده داده و مستقل از آن است. هیچ‌کدام در Git قرار نمی‌گیرند.

روش دستی در صورت نداشتن Python روی میزبان: .env.example را به .env کپی، ADMIN_TOKEN را تعیین و `docker compose up -d --build` را اجرا کنید. برای Linux/macOS، start.sh از python3 استفاده می‌کند.

## آنچه در اولین اجرا رخ می‌دهد

- PostgreSQL ایجاد و migrationهای 0001 تا 0003 اعمال می‌شوند.
- هشت فایل واقعی تاریخچه Data وارد می‌شوند؛ ۱۰٬۲۲۷ رکورد موجود با منبع repository و برچسب تاریخی حفظ می‌شوند. نام کامل صندوق‌ها از آخرین snapshot موجود در همان مخزن خوانده می‌شود.
- یک کار «دریافت همه نمادها» در صف بانک ساخته می‌شود. این راه‌اندازی اولیه در نصب مجدد، کار موجود را دوباره نمی‌سازد.
- API، Scheduler و Collector مستقل اجرا می‌شوند. پنل از بانک می‌خواند؛ بستن مرورگر، دریافت را حذف نمی‌کند.

وجود داده اولیه مخزن شرط عملکرد نیست. اگر Data خالی باشد، پنل حالت خالی دارد و دریافت نمادها از منبع آغاز می‌شود.

## صفحات

| صفحه | کارکرد |
|---|---|
| نمای کلی | تعداد واقعی نماد، رکورد و آرشیو؛ تاریخ پوشش؛ دیده‌بان؛ نمودار قیمت و فعالیت دریافت |
| نمادها | جست‌وجوی فارسی/عربی، نام یا ins_code؛ آخرین قیمت، حجم و تاریخ؛ پروفایل و پوشش داده |
| مرکز همگام‌سازی | دریافت همه یا نمادهای منتخب؛ انتخاب TSETMC/BrsApi؛ مکث، ادامه و دریافت دوباره؛ گزارش مراحل |
| کاوش داده‌ها | مرور مجموعه‌داده‌های ساختاریافته، صفحه‌بندی و نمایش رکورد خام |
| منابع و سرویس‌ها | وضعیت واقعی دریافت‌ها، پاسخ کامل، کاتالوگ و فراخوانی دستی سرویس با پارامترهای واقعی |

در پروفایل نماد، تاریخچه CSV قابل دریافت است. برای قیمت روزانه در نمودار، در صورت وجود چند منبع، TSETMC سپس BrsApi سپس فایل مخزن اولویت دارند؛ داده اصلی هر منبع مستقل نگه داشته می‌شود.

## دریافت کامل و محدوده پوشش

«همه نمادها» یعنی کشف نمادها از دیده‌بان و سپس برنامه‌ریزی دریافت برای همه نمادهای فعال بانک. هیچ فهرست محدود ثابت از سهام در collector وجود ندارد. در صورت انتخاب چند نماد، همان‌ها پس از تعیین شناسه منبع بررسی می‌شوند.

Collector از کاتالوگ ۱۳۶ مسیر برای سرویس‌های عمومی و سرویس‌های قابل پارامتردهی نماد استفاده می‌کند. aliasهایی که یک URL را تولید می‌کنند دوباره فراخوانی نمی‌شوند. اطلاعات پایه، قیمت و تاریخچه کامل روزانه، رویدادهای تعدیل، حقیقی/حقوقی، دفتر سفارش، ریزمعاملات، وضعیت، آمار، سهامداران، پیام ناظر، اطلاعیه‌ها و صندوق‌ها، متناسب با سرویس موجود، درخواست می‌شوند. تمام payload موفق منبع در بانک نگه داشته می‌شود؛ همه خانواده‌ها الزاماً مدل ستونی اختصاصی ندارند و داده تخصصی ممکن است در observations یا پاسخ خام باشد.

دریافت روزانه قیمت از Top=0 مستندشده همان endpoint استفاده می‌کند. این مقدار برای سایر سرویس‌ها فرض نمی‌شود. در سرویس‌های دارای Top، مقدار ۱۰۰۰ استفاده و در params ذخیره می‌شود؛ سقف یا عمق قابل ارائه خود منبع ممکن است محدود باشد. قرارداد کاتالوگ عمومی، فهرست رسمی تضمین‌شده تمام سرویس‌های TSETMC نیست.

برای ریزمعاملات و دفتر سفارش تاریخی، بازه شمسی در فرم وارد شود. برنامه تاریخ‌ها را به میلادی موردنیاز TSETMC تبدیل می‌کند. بدون بازه، فقط آخرین تاریخ قابل اثبات از داده منبع/تاریخچه موجود درخواست می‌شود. روز تعطیل ممکن است پاسخ خالی داشته باشد؛ هیچ داده‌ای برای آن ساخته نمی‌شود. نوع تعدیل فایل‌های اولیه unknown است.

سرویس‌هایی با پارامتر ویژه مثل شماره پیگیری اطلاعیه، شناسه حراج، شناسه سهامدار یا طبقه‌بندی اختصاصی با عدد ساختگی فراخوانی نمی‌شوند. موارد بدون شناسه در نتیجه برنامه‌ریزی ثبت می‌شوند. کاربر می‌تواند از «منابع و سرویس‌ها» همان endpoint را با شناسه واقعی اجرا کند؛ پاسخ آن نیز ذخیره می‌شود. برای NAV، فقط صندوقی که طبقه‌بندی آن در اطلاعات مرجع مشخص باشد خودکار درخواست می‌شود.

در BrsApi، فهرست نمادها در پنج دسته، شاخص‌ها و گروه‌های IME/کامودیتی و کدال دریافت می‌شوند؛ سپس Symbol، History type=0/1، Candlestick type=1/2/3، سهامداران و ریزمعاملات تاریخ‌دار هر نماد برنامه‌ریزی می‌شوند. ادامه صفحات کدال به مرحله بعدی صف منتقل می‌شود تا خطای شبکه یا سهمیه، کار انجام‌شده را از بین نبرد.

## وضعیت‌های دریافت

| وضعیت | معنی |
|---|---|
| در انتظار | مرحله در بانک ذخیره است و Collector آن را اجرا خواهد کرد |
| در حال دریافت | یک درخواست یا مرحله برنامه‌ریزی در اجرا است |
| دریافت موفق | داده معتبر پاسخ، ذخیره شده است |
| پاسخ خالی | پاسخ معتبر بدون رکورد؛ معادل داده کامل یا خطا نیست |
| بایگانی‌شده | متن/CSV یا باینری به‌صورت پاسخ خام نگهداری شده است |
| نیاز به بررسی | بخشی از داده نامعتبر، ناقص یا دریافت‌نشده است |
| مکث شده | مکث کاربر یا خطای اتصال/احراز هویت/سهمیه؛ قابل ادامه |

مکث، پس از پایان درخواست در حال اجرا اعمال می‌شود. هنگام ادامه، مراحل موفق حفظ و مراحل ناموفق دوباره در صف قرار می‌گیرند. worker از قفل مشترک PostgreSQL استفاده می‌کند؛ چند فرایند نباید یک task را هم‌زمان دریافت کنند. lease ده‌دقیقه‌ای برای بازیابی task مانده از فرایند قطع‌شده وجود دارد. برای دریافت دوباره پس از پایان کامل، کار جدید ایجاد می‌شود.

## ساختار ذخیره‌سازی

| بخش | جداول |
|---|---|
| مرجع | symbols، indices |
| داده ساختاریافته | price_history، client_type_history، candlesticks، transactions و ۱۲ مجموعه دیگر |
| تمام پاسخ‌ها | raw_responses و provider_requests؛ منبع، params، payload و hash |
| مشاهدات عمومی | market_observations؛ شناسه نماد، تاریخ، کلاس داده و quality |
| صف پایدار | collection_jobs و collection_tasks |
| اعتبارسنجی | sync_errors و sync_runs |

پاسخ اصلی منبع و فیلدهای ناشناخته حذف نمی‌شوند. رکورد نامعتبر در قرنطینه ثبت می‌شود. قیمت/ارزش Decimal، ins_code رشته و شمارنده صحیح است؛ مقدار صفر حفظ می‌شود. نام نماد فارسی/عربی نرمال می‌شود و منابع مختلف همدیگر را بازنویسی نمی‌کنند.

## API اضافه‌شده برای پنل

- GET /api/dashboard، /api/stocks، /api/stocks/{l18}
- GET /api/stocks/{l18}/export و /api/datasets
- GET /api/collections
- POST /api/admin/collections
- POST /api/admin/collections/{id}/pause و /resume

عملیات دریافت به X-Admin-Token نیاز دارد. READ_TOKEN اختیاری است. کلید نشست پنل در sessionStorage قرار می‌گیرد و کلید ارائه‌دهنده به مرورگر برگردانده نمی‌شود. متن داده منبع قبل از نمایش HTML escape می‌شود؛ JSON خام با textContent نمایش داده می‌شود.

## محدودیت واقعی اتصال

برنامه و بانک قابل اجرا هستند؛ دریافت تازه به دسترسی شبکه و حساب منبع نیاز دارد. در این جلسه، سرویس بیرونی پاسخ داده جدید معتبر نداده است. برنامه این حالت را به صورت job مکث‌شده ثبت می‌کند. داده اولیه مخزن به‌عنوان داده زنده نمایش داده نمی‌شود. توضیح و شواهد محیط در گزارش اعتبارسنجی آمده است.

## نگهداری

برای توقف از docker compose down استفاده کنید؛ گزینه -v داده volume را حذف می‌کند. پشتیبان‌گیری:

```bash
docker compose exec -T db pg_dump -U market market > market_backup.sql
```

زمان‌بند تهران و مستقل از باز بودن پنل است. داده خام retention خودکار ندارد؛ اندازه بانک و سیاست پشتیبان‌گیری متناسب با تعداد نماد و تاریخچه درون‌روزی تنظیم شود. Docker image شامل .env و پایگاه توسعه نیست.
