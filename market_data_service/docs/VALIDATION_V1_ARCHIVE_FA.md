# گزارش تحویل و اعتبارسنجی

تاریخ: ۱۲ نوامبر ۲۰۲۶

## نتیجه قابل اتکا

کد، schema، مهاجرت، API، زمان‌بند، تنظیمات، Docker Compose و آزمون‌ها آماده‌اند. ۵۰ آزمون محلی موفق شده‌اند. یک آزمون ویژه PostgreSQL به علت نبود سرویس PostgreSQL در این محیط اجرا نشده است. ادعای دریافت موفق داده واقعی با کلید حساب شما مطرح نمی‌شود.

| بررسی | نتیجه و حدود اعتبار |
|---|---|
| Client هر ۱۶ سرویس | مسیر و پارامترها در کد تعریف شده، fixtureهای HTTP ساختگی برای همه دسته‌ها ذخیره شده‌اند |
| قراردادهای عمومی منبع | صفحات رسمی و نمونه‌های عمومی کدال، IME و کندل بررسی شده‌اند؛ کلید حساب استفاده نشده است |
| آزمون رفتاری | ۵۰ موفق؛ retries، 429، 401/403، HTML خطا، خطای JSON، درج/به‌روزرسانی، قرنطینه و مسیر API |
| اصلاح داده | قیمت صفر، تغییر قیمت همان روز، ثبت ابطال معامله، جداسازی نوع کندل و legهای اختیار |
| تاریخ | تبدیل شمسی/میلادی/ارقام فارسی؛ جلوگیری از تاریخ‌گذاری حدسی ریزمعاملات؛ زمینه تاریخ کندل لحظه‌ای |
| Scheduler | تعریف سه job و timezone تهران، اجرای منطقی daily و weekly با MockTransport |
| Migration | upgrade، alembic check و downgrade روی SQLite موقت موفق؛ schema بدون اختلاف با مدل |
| PostgreSQL DDL | SQL برای ۲۱ جدول با JSONB، NUMERIC(30,6)، BIGSERIAL و FK کامپایل شد |
| PostgreSQL واقعی | اجرا نشده؛ آزمون اختصاصی و workflow برای اجرا فراهم است |
| Docker واقعی | اجرا نشده؛ Docker در محیط حاضر نصب نیست |
| OpenAPI | تولید موفق و فایل docs/openapi.json در بسته موجود است |
| API زنده با کلید حساب | انجام نشده؛ بررسی خودکار ارسال credential را بدون اجازه صریح پیام گفتگو رد کرد |

آزمون‌ها یک هشدار deprecation از TestClient/HTTPX نسخه محیط دارند؛ آزمون شکست‌خورده وجود ندارد. خروجی خام در test_output.txt موجود است.

## یافته‌های فایل app.py اولیه

۱. وابستگی به templates/index.html دارد ولی این فایل ضمیمه نشده است؛ صفحه اصلی با فایل‌های موجود کامل نیست.
۲. بانک SQLite و ستون‌های REAL به‌کار رفته، درحالی‌که سند PostgreSQL/MySQL و مدل جامع داده می‌خواهد.
۳. کلید در سورس پیش‌فرض است و GET تنظیمات آن را برمی‌گرداند؛ در نسخه جدید کلید در env است و مسیر بازگرداندن آن وجود ندارد.
۴. init_db و شروع background sync در زمان import اتفاق می‌افتند؛ در نسخه جدید migration و worker صریح‌اند.
۵. ساختار تاریخچه و چند سرویس فراهم است، ولی پوشش کامل IME، مایگریشن و آزمون‌های درخواست‌شده وجود ندارد.
۶. در چند محاسبه استفاده از `or` برای مقدار عددی، صفر معتبر را به fallback تبدیل می‌کند؛ نگاشت جدید این رفتار را ندارد.
۷. تاریخ ریزمعاملات بدون تاریخ صریح با امروز برچسب می‌خورد، درحالی‌که قرارداد سرویس آخرین روز معاملاتی را می‌دهد؛ نسخه جدید تاریخ را صریح تعیین می‌کند.

فایل اصلی تغییر نکرده است. بسته جدید، بک‌اند مستقل داده است؛ UI و منطق امتیازدهی معاملاتی برنامه قبلی در آن بازتولید نشده‌اند.

## شرایط پذیرش نهایی در محیط شما

- اجرای Docker و migration روی PostgreSQL واقعی؛ فعال‌کردن آزمون PostgreSQL با بانک اختصاصی.
- اجرای verify-live با اجازه استفاده از کلید و بررسی دسترسی جداگانه هر سرویس/پلن.
- بررسی حداقل یک نماد، یک صندوق و یک روز معاملاتی با مرجع داده؛ API ممکن است برای روز فاقد معامله پاسخ خالی بدهد.
- تنظیم ظرفیت دریافت متناسب با سهمیه، تعداد نماد و اندازه تاریخچه.

این مراحل در این محیط تأیید نشده‌اند و باید پیش از اتکا به دریافت داده واقعی تکمیل شوند.
